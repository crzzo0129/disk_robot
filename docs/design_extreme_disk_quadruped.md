# 极端圆盘躯干四足机器人设计文档

## 目标

本项目研究一种可以在“正常四足行走”和“收腿后滚动”之间切换的四足机器人。当前确定的第一版形态不是球形机器人，也不是独立轮胎式身体，而是一个正常四足布局的机器人：从侧面看，躯干接近一个圆；从前面看，躯干仍然是较窄的厚度。腿部连接点位于圆形躯干偏下侧，保留前腿和后腿的基本四足布局。

第一阶段先使用抽象 MJCF 模型，而不是直接修改 Pupper v3。这样可以优先回答核心研究问题：躯干外形和腿部连接点位置如何影响站立、行走、收腿姿态和滚动能力。

## 当前形态假设

- 躯干：薄圆盘/圆柱碰撞体，侧视近似圆形，前视是窄矩形厚度。
- 腿部：四条简化三自由度腿，每条腿包含 `hip_abd`、`hip_flex`、`knee`。
- 连接点：前腿和后腿仍按正常四足的前后方向布置，连接在圆盘偏下侧，而不是圆盘水平直径的极端端点。
- 初始任务：先验证模型结构、站立姿态、收腿姿态和基础碰撞，再进入行走与滚动训练。

当前第一阶段模型文件：

- `assets/disk_quadruped_extreme.xml`
- `scripts/view_extreme_disk_pose.py`
- `tests/test_disk_quadruped_model.py`

## 阶段规划

### 阶段 1：抽象模型

建立极端圆盘躯干四足的 MJCF 模型，先不追求真实机械细节。验收重点是：

- MuJoCo 能加载 XML。
- MJX 后续可以读取模型。
- 模型包含薄圆盘躯干、四条三自由度腿、前后/左右命名清晰的 hip anchor。
- 至少有 `stand` 和 `folded` 两个 keyframe。
- 能通过脚本查看站立和收腿姿态。

### 阶段 2：行走训练

在平地上训练正常四足行走。此阶段不要求滚动，只要求圆盘躯干不会让行走问题完全不可学。可以参考现有 `robot_curl_mjx` 的 Brax/MJX 训练入口，但需要新建独立的 walk task config 和 reward。

### 阶段 3：滚动训练

从已知收腿姿态开始训练滚动。先假设 `folded` 姿态由人工定义，策略只学习如何通过腿部或质心扰动让圆盘躯干持续向前滚动。奖励重点包括前向位移、躯干角速度、保持收腿、减少不必要碰撞。

### 阶段 4：形态切换训练

先从静止状态训练两个方向：

- 站立到收腿滚动。
- 收腿滚动姿态到站立。

之后再考虑动态行走到滚动、滚动到行走的连续切换。

## 关键建模参数

后续实现应尽量把这些参数集中管理，方便比较不同构型：

- 圆盘半径。
- 圆盘厚度。
- 前后腿连接点的 x 坐标。
- 左右腿连接点的 y 坐标。
- 连接点相对圆心的高度。
- 大腿和小腿长度。
- `folded` 姿态中髋、膝关节角度。
- 脚端球半径和摩擦参数。

## 当前默认取舍

- 第一版使用薄圆盘/圆柱，不使用球体近似。
- 第一版使用抽象 MJCF，不直接从 Pupper v3 改。
- Pupper v3 暂时作为后续真实腿长、关节范围和行走任务的参考。
- 现有 `robot_curl_mjx` 训练框架可以复用思路，但不直接把当前 curl 环境改成 disk quadruped 环境。

## 收腿与滚动切换策略假设

当前 `stand` 和 `folded` 是人工标定的暂定标准姿态，但从站立到收腿不应只依赖简单线性插值。因为躯干是 disk 型，腹部为弧形，当前后腿同时收起到一定高度时，机器人可能进入不稳定状态。

后续切换策略建议使用分阶段逻辑：

- 在躯干中心高度较高时，可以允许前后腿同步向 `folded` 姿态靠近。
- 当 `torso` 中心高度下降到阈值附近，例如 `z <= 0.25`，切换为前后腿分阶段收起。
- 向前滚动时，优先收前腿，使质心和接触状态产生向前滚动的趋势；随后再收后腿完成折叠。
- 反向或其他滚动方向可以镜像该顺序：先收目标滚动方向一侧的腿，再收另一侧。
- 训练初期可以把该顺序作为 scripted curriculum 或 reference trajectory，之后再让策略学习是否偏离该轨迹。

这个假设会影响阶段 3 和阶段 4 的 reward / reset / curriculum 设计：奖励不仅要看最终是否接近 `folded`，还要记录躯干高度、前后腿折叠进度、圆盘角速度和接触转移是否符合预期。

## 2026-07-02 阶段 1 冻结记录

阶段 1 的目标是得到第一版可加载、可查看、可控制、可诊断的抽象 MuJoCo/MJCF 模型。当前冻结基线如下：

- 模型文件：`assets/disk_quadruped_extreme.xml`。
- 机器人形态：正常四足布局，躯干为极端 disk/cylinder 形状，侧视接近圆盘，前视保持窄厚度。
- 姿态基线：`stand` 和 `folded` 两个 keyframe 均由人工标定，后续训练优先引用它们。
- actuator 基线：保留 12 个单独 position actuator，不在 XML 中增加会物理耦合前后腿的 tendon/group actuator。
- 工具脚本：
  - `scripts/view_extreme_disk_pose.py`
  - `scripts/control_extreme_disk_flex.py`
  - `scripts/interpolate_extreme_disk_pose.py`
  - `scripts/diagnose_extreme_disk_pose.py`

诊断结论：

- `stand` 第一帧四足接地，但脚球存在穿入地面的接触初值；这解释了 passive viewer 卡在第一帧时脚看起来在地面下方的现象。
- `folded` 第一帧躯干接地、脚已收高，但存在脚与躯干的内部接触；后续训练前需要继续关注碰撞组或姿态微调。
- 当前阶段暂不继续调整 XML。后续如果需要更物理干净的初始状态，应作为独立小迭代处理，避免混淆第一版实验基线。

后续训练策略记录：

- 从 `stand` 到 `folded` 不建议只使用全程同步插值。
- 当 torso 中心高度下降到阈值附近，例如 `z <= 0.25`，应切换到分阶段收腿。
- 向前滚动时建议先收前腿，再收后腿，用重心偏移帮助圆盘躯干启动滚动。
